feat(middleware): enhance auth logging and error handling

INTENT:
- Fix server crashes from unhandled JWT Promise rejections
- Improve token validation and error handling flow
- Prevent error propagation in auth middleware chain
- Add better validation for token structure and user existence

IMPLEMENTATION:
- Added proper Promise rejection handling for JWT verification
- Added proper error handling to prevent server crashes:
  * Stop error propagation with return statements
  * Send appropriate 401/403 responses for auth failures
- Enhanced token validation error reporting with detailed info:
  * Token value in error logs
  * Stack traces for errors
  * Timestamp information and validation
  * Token expiry time difference calculations
- Fixed syntax issues and improved code structure in auth-logger.js
- Removed upload endpoint skip conditions for consistent logging
- Added HTTP status codes (401/403) with clear error messages
- Added framework for future token recovery mechanism

KNOWN ISSUES/CONSIDERATIONS:
- Token recovery mechanism is currently just logging attempts
- Upload endpoints now have duplicate basic logging (from both auth-logger and upload-logger)
- This may increase log volume in production
- JWT verification errors are now always returned as 401s for consistent client handling
